【AI 转型】Java 工程师补 AI 理论基础的学习地图

前言

写转型系列到现在，评论区问得最多的一类问题是：

「你写的那些 Spring AI、LangChain4j、RAG 我都能照着做，但面试官一问『Transformer 里注意力是怎么算的』『LoRA 为什么能省显存』我就卡住了。要不要先去补数学？补到什么程度？」

这个问题有两种典型错误答案。

错误答案一：不用补，会调框架就行。
短期能找到活干，但天花板极低。模型选型、参数调优、成本核算、效果归因，这些「值钱的事」全部需要理论直觉。而且一旦模型升级、框架换代，纯 API 知识归零。

错误答案二：从头学机器学习。
买《统计学习方法》+ 吴恩达 + 3Blue1Brown，从线性回归推到反向传播，两个月后放弃。原因是没有目标函数：你不知道学到哪一步算够，也不知道学的这部分在工程里对应什么。

这篇给第三种答案：只学「够用」的 20%，并且用 Java 工程师擅长的方式学——写代码验证，而不是推公式。

一、先定义「够用」：三个可检验的能力

转型做 AI 应用开发（不是算法岗），理论只需要支撑三件事：

能力 具体表现 对应的理论
能解释 别人问「为什么温度调低输出更稳定」「为什么长上下文贵」时，能讲清机制而不是背结论 概率分布、softmax、注意力复杂度、KV Cache
能算账 给定 QPS、上下文长度、模型规格，能算出 Token 成本、显存需求、并发上限 参数量、显存构成、FLOPs 估算、缓存
能调参 检索效果差时，能判断是切分、Embedding、还是重排的问题 向量空间、相似度度量、距离集中现象

不需要：手推反向传播、实现 CUDA kernel、复现论文。那些是算法岗的活。

一条自检标准：你能不能在白板上画出「一句话从输入到输出」的全链路，并在每个环节标出一个可调参数和它的代价？ 能，就够用了。

二、四层知识地图：明确「学到哪停」

关键判断：L0 + L1 是地基（约 3 周），L2 是按需插件（每个主题 2~3 天），L3 碰都不要碰（除非你转算法岗）。

三、60 天计划：每周一个「能跑的东西」

原则：每周产出一个可运行、可验证的 Java 代码或数字。不产出代码的学习，第二周就会忘。

Week 1（Day 1-7）：向量与概率的最小集

目标：把「Embedding 是什么」「softmax 在干什么」变成肌肉记忆。

天 内容 产出（Java）
1 向量、点积、范数、余弦相似度 Similarity.java：手写 cos/dot/L2，对比 java-vector-api 版本性能
2 归一化为什么让点积=余弦 实验：未归一化 vs 归一化后 top-10 检索结果差异
3 softmax：为什么是指数、为什么减最大值 Softmax.java：实现带 max-shift 的数值稳定版，对比溢出行为
4 温度 / top-p / top-k 用固定的 logits 数组（不用真模型）模拟采样，观察温度对分布的影响
5 交叉熵与困惑度 给定「正确 token 概率」，算 CE 与 PPL，理解「loss 2.3 ≈ PPL 10」
6 熵与「模型有多不确定」 计算不同温度下的熵曲线，画出「温度-多样性」关系

Week 2（Day 8-14）：注意力机制，用 80 行 Java 写出来

目标：不再把 Transformer 当成黑盒。

天 内容 产出

核心代码骨架：

写完这段代码，你会突然理解三件事：

  1. 为什么上下文越长越贵：scores 是 n×n 矩阵，n=128k 时是 160 亿个数；
  2. 为什么 KV Cache 能省算力：decode 阶段 Q 只有 1 行，K/V 是历史的，所以缓存 K/V 就够；
  3. 为什么「Lost in the Middle」存在：注意力权重是 softmax 出来的，中间位置的竞争最激烈。

检验标准：能在白板上写出 softmax(QKᵀ/√d)V，并解释每个符号的维度和作用。

Week 3（Day 15-21）：训练三阶段与「为什么微调很贵」

目标：能判断「这个需求该用 Prompt、RAG 还是微调」。

天 内容 产出
15 预训练：下一个 token 预测 用一段文本手算「给定前 3 个词，第 4 个词的概率」的直觉
16 SFT：为什么需要指令数据 对比「续写」与「问答」的任务形式差异
17 RLHF / DPO：偏好对齐在解决什么 写出「两个回答 + 偏好标签」的训练信号形式
18 LoRA：秩分解为什么省参数 手算：d=4096, r=8 时，全参 vs LoRA 的参数量比
19 量化：INT8/INT4 的误差从哪来 用 Java 模拟 fp16→int8 量化-反量化，看余弦相似度掉多少
20 过拟合与数据量 估算「1000 条 SFT 数据能学会什么、不能学会什么」
21 复盘：选型决策树 画出 Prompt / RAG / 微调 的决策图

LoRA 的参数量手算（这是面试高频题）：

为什么省的不只是参数：LoRA 冻结了原权重，梯度不需要对原权重计算，优化器状态（Adam 的 m/v，各一份 fp32）也不用存。显存节省 ≈ 参数节省 × 3~4（权重梯度 + 两个动量）。

检验标准：能回答「为什么 LoRA 的 r 不能随便调大」，以及「为什么 LoRA 不适合教模型全新知识」。

四、学习资源的挑选原则（比资源清单更重要）

  1. 优先「带可运行代码」的。纯数学推导的视频看到第三集必然走神；能跑起来、能改参数看结果的材料，记忆留存率高 5 倍以上。
  2. 论文只读摘要 + 方法图 + 实验表格。80% 的论文价值在这三处，剩下的公式细节对应用开发无用。
  3. 不要追新模型。半年一个新 SOTA，追不完。把 Transformer / 注意力 / KV Cache 这三个十年不变的东西学透，新模型只是「换了归一化位置、换了激活函数」。
  4. 用 Java 写实验，不要为了学习去学 Python 生态。你已经有 JVM、有调试器、有单元测试，用 double[][] 手写一遍注意力，比在 Notebook 里调库学到的多得多。
  5. 每学一个概念，问一句「这在工程里对应什么参数」。对应不上的，大概率是 L3，跳过。

五、六个常见误区

误区 为什么错 正确做法
把 Prompt 工程当 AI 理论 Prompt 是接口设计，不是原理。只会 Prompt 的人无法解释「为什么换个模型就失效」 Prompt 之外补 L0/L1
只看视频不写代码 看完觉得懂了，一写就废 每周必须有可运行的 Java 产物
一头扎进反向传播 应用开发 99% 的场景用不到手推梯度 知道「梯度下降在最小化损失」就够
迷信「先学 Python 再学 AI」 语言不是门槛，概念才是 用 Java 写实验，概念一样通
追逐论文数量 半年后全部过时 只读奠基性论文（Attention is All You Need、LoRA、DPO）的图和结论
学完不输出 无法验证是否真懂 每两周写一篇「用 Java 解释 XX」的笔记

七、面试怎么用：三层回答模板

被问「你了解 Transformer 吗」，不要背百科。用三层结构：

第一层：机制（30 秒）
「Transformer 的核心是自注意力。每个 token 生成 Q、K、V 三个向量，用 Q 和所有 K 做点积算相关性，除以 √d 防止 softmax 饱和，softmax 归一化成权重后加权求和 V。多头是把这个过程并行做多份，让不同头关注不同模式。解码时用因果 mask 保证只能看到前面的 token。」

第二层：工程含义（60 秒）
「从工程角度它决定了三件事：一是上下文长度平方级成本，因为注意力矩阵是 n×n；二是 KV Cache 能大幅降低 decode 阶段算力，因为历史 token 的 K/V 可以复用；三是位置编码决定长文本外推能力，RoPE 的插值方案是现在长上下文的主流做法。」

第三层：取舍（30 秒）
「所以做 RAG 时我不会一味堆上下文：8k 上下文单请求 KV Cache 就 1GB，同等显存下并发直接砍半。这也是为什么长上下文和 RAG 是互补而不是替代——RAG 把无关内容挡在外面，长上下文解决「必须一起看」的场景。」

这个结构的好处：每一层都能被追问，而每一层你都答得出来。纯背定义的人在第一层之后就会卡住。

八、30 / 60 / 90 天检查清单

30 天（L0 完成）

  • 能手算两个向量的余弦相似度
  • 能解释温度、top-p、top-k 各自改变什么
  • 能说清 token 与字符、字节的关系（中文为什么按 1~2 token 算）
  • 能算出「一次请求的 Token 成本」

60 天（L1 完成）

  • 能手写单头注意力（80 行内）
  • 能解释 KV Cache 省的是什么算力
  • 能算 7B/13B/70B 模型的权重显存
  • 能画出训练三阶段的对比表
  • 能判断一个需求该 Prompt / RAG / 微调

90 天（L2 起步）

  • 能手算 LoRA 的参数量与显存节省
  • 能解释 INT8 量化为什么会让余弦相似度下降
  • 能看懂 HNSW 的 m / ef_construction / ef_search 三个参数
  • 能设计一个包含黄金集的评测方案
  • 能在面试中完整回答「长上下文 vs RAG」

总结

  • 转型做 AI 应用开发，理论不需要「学完机器学习」，只需要支撑解释、算账、调参这三件事。
  • 用四层地图划定边界：L0 必备、L1 需理解、L2 按需、L3 不必。大部分人的问题是把 L3 当成 L0 来学，然后在第二周放弃。
  • 学习方式要匹配 Java 工程师的习惯：写代码验证，不推公式。80 行手写注意力 > 看 10 小时视频。
  • 每周必须有产出物（代码或数字），否则「感觉懂了」会在两周内归零。
  • 理论和工程要绑定：每学一个概念，问「这在工程里对应哪个参数、什么代价」。答不上来的，就是不需要学的。

理论的意义不是让你在面试里背定义，而是让你在别人都在调参试错的时候，能直接说出「这个方向不对」。这中间的差距，大概就是 60 天。
